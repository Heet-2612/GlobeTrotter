# GlobeTrotter 926 Activities: Data-Driven Image Curation Plan

## Executive Summary

This document presents a data-driven image strategy for the 926 pre-seeded GlobeTrotter activities. Instead of manually sourcing 926 unique image files, this strategy groups activities into 18 primary categories and 46 subcategories, classifying each by visual requirements:

- **Total Pre-seeded Activities**: `926`
- **Activities Assigned to Image Pools (`SHARED_IMAGE_POOL` / `UNIQUE_IMAGES`)**: `886` (95.7%)
- **Activities Designated as `NO_IMAGE`**: `40` (4.3%)
- **Total Curated Images Required**: `128` images
- **Curation Reduction**: **86.2% reduction** (from 926 images down to 128)

## 4. Activities with Complex / Dual-Category Ambiguity

The following types of activities span multiple visual concepts and were classified by primary feature:

1. **Fort & Lake Combinations** (e.g. *Amber Fort*, *Lake Pichola Island Palaces*): Assigned to `FORTS_PALACES` or `BACKWATERS_BOATING` based on whether the primary experience is land-based architecture or water navigation.
2. **Rock-Cut Cave Temples** (e.g. *Ajanta Caves*, *Ellora Caves*, *Badami Caves*): Combines religious and cave elements. Assigned to `CAVES_ROCK_FORMATIONS` -> `ROCK_CUT_CAVE_TEMPLES` due to distinct subterranean stone carving visuals.
3. **Palace Museums** (e.g. *Umaid Bhawan Palace Museum*, *City Palace Museum*): Combines palace architecture and museum exhibits. Assigned to `FORTS_PALACES` or `MUSEUMS_GALLERIES` based on whether the primary tour is exterior/palace grounds or interior artifact halls.
4. **High-Altitude Passes** (e.g. *Khardung La*, *Rohtang Pass*): Combines motorable road and mountain pass scenery. Assigned to `TREKKING_HIKING` -> `HIGH_ALTITUDE_MOUNTAIN_TREKS` due to alpine mountain visuals.

## 5. Small Subcategories & Low-Value Image Allocations

The following subcategories were designated as `NO_IMAGE` (0 image allocation) because dedicated images add minimal visual value:

- **`ICONIC_EATERIES_DINING`** (28 activities): Standard indoor dining at named restaurants. Highly specific or generic indoor dining adds little value compared to high-impact destination images.
- **`LOCAL_STREET_MARKETS`** (12 activities): Routine local vegetable and grocery shopping stalls.
- **`SCIENCE_THEMATIC_MUSEUMS`** (0 allocated): Minor planetariums/wax exhibits covered sufficiently by fallback icons.
- **`ZOOS_ANIMAL_PARKS`** (0 allocated): Standard municipal animal parks where destination scenery is preferred.

## 7. Recommended Database & Schema Architecture

To support this flexible, tiered image resolution model cleanly without hardcoding image URLs on all 926 database rows, we recommend the following relational schema strategy:

```sql
-- 1. Category Image Pool Registry
CREATE TABLE activity_category_images (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    category_id VARCHAR(64) NOT NULL,
    subcategory_id VARCHAR(64) NOT NULL,
    image_url VARCHAR(1024) NOT NULL,
    caption VARCHAR(255),
    source_attribution VARCHAR(255),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. Activity Entity Updates (Nullable direct_image_url)
ALTER TABLE activities 
ADD COLUMN subcategory_id VARCHAR(64),
ADD COLUMN image_url VARCHAR(1024) NULL, -- NULL indicates fallback to category pool
ADD COLUMN image_strategy VARCHAR(32) DEFAULT 'SHARED_IMAGE_POOL';
```

### Runtime Image Resolution Fallback Logic

```text
1. If activity.image_url IS NOT NULL -> Use activity.image_url (Specific high-priority image)
2. Else if subcategory image pool exists -> Pick deterministic pool image (e.g. hash(activity.id) % pool.size)
3. Else if parent category image pool exists -> Pick deterministic parent category image
4. Else -> Return NULL (Frontend displays elegant SVG category icon placeholder)
```
